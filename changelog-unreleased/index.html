Unreleased​

Breaking changes​

  • 247Sports site pages: primary_color, jersey and postal_code are String (were Int64 when every value was digits, so event "000000" was 0); a (0, 0) latitude / longitude pair, 247's no-location sentinel, is null. (#928)
  • fox_nfl_pbp / fox_cfb_pbp: play_team is now the club code of the drive group the play is filed under (e.g. "NYG"); it held the name of the player Fox credits the play to, which moves to the new play_player column. (#922)
  • ncaa_{mbb,wbb}_play_by_play / ncaa_{mbb,wbb}_box_scores raise AssetFetchError when a fetch fails (a ban, an exhausted pool, an uncleared challenge) instead of dropping that game, which made a ban read as a smaller season; errors="skip" keeps going and adds a scrape_status column with one row per dropped game saying why. (#924)
  • nfl.update_config(cache_mode=...) raises ValueError for a mode other than "memory", "filesystem" or "off" (an unknown mode used to switch caching off silently).
  • nfl_players_crosswalk() raises AssetFetchError when the nflverse players master cannot be fetched; it used to return a zero-row frame ("never a raise"), which nulled every id in a join. An absent asset still gives zero rows, and a failed DynastyProcess load now warns (yahoo/cbs ids null).
  • Bart Torvik: torvik_player_stats() / parse_torvik_player_stats() return number as String (was Int64); the 8 "00" jerseys of 2025 no longer merge into the 291 0 rows. (#928)
  • Basketball-Reference: bref_team_roster() returns number as String (was Float64), so Robert Parish's "00" is no longer 0.0; any other zero-padded column also stays String. (#928)
  • ESPN game rosters: espn_<lg>_game_rosters(raw=True) (mbb, wbb, nba, wnba, nfl, nhl, cfb) returns the Core v2 competitors payload (a dict); raw= was accepted and ignored, so it returned the parsed frame. (#878)
  • ESPN schedules: the six copies that sent seasonType now send seasontype. ESPN ignored the camelCase key, so season_type= with dates=YYYY&week=N (NFL, NHL, WNBA, NBA, MBB, WBB) never filtered; it does now, and those calls return different rows. (#855)
  • KenPom: the jersey column is String on every page and renamed to jersey: team / team_players_expanded player_table* column_0 -> jersey (was Float64) and box table_* column_0_rk -> jersey (was Int64). A season of pages stacks without a String / Float64 clash, and no jersey reads "2.0". (#928)
  • NBA / WNBA / MBB / WBB pbp: espn_<lg>_pbp plays keep the names coordinate.x / coordinate.y but change their meaning and dtype. They were ESPN's raw feet (hoop at (25, 0)); they are now the hoopR / wehoop full-court frame the published files use (x = y - 41.75, y = x - 25, both negated on home-team plays), always Float64. ESPN's values move to the new coordinate.x.raw / coordinate.y.raw (coordinate_x_raw / coordinate_y_raw once snake-cased), except on the free throws hoopR / wehoop's "Free Throw" match finds (NBA / WNBA), where the raw pair holds the pinned (25, 13.75), as in the published files. ESPN's missing-location sentinel reads about +-2.1e8 after the transform; filter on coordinate_x_raw > nba_game_page.COORD_SENTINEL. The release converters (helper_<lg>_play_by_play) rebuild from the raw pair, so a processed payload converts once.
  • NFL, CFB: processed plays keep their documented Float64 for the EP/WP family, first_down_prob, prob_2pt and drive_start (they were Float32 when a model scored), with no value change, and NFL teamParticipants has one struct field order; create_box_score(plays_frame) still reproduces advBoxScore exactly. (#797)
  • NFL: sportsdataverse.nfl.model_vars.qbr_vars is in the QBR trainer's order (qbr_epa, pass_epa, rush_epa, sack_epa, pen_epa, spread), and nfl/models/qbr_model.ubj is re-saved with those feature names (same trees), so a frame in the old column order raises instead of scoring permuted inputs. (#795)
  • NFL: the current season flips on the Wednesday after Labor Day and week 1 starts on the Thursday after it (nflreadr's rules; week read one high in 2015-16, 2020-22, 2026-27); nfl_schedule.most_recent_nfl_season and nfl_schedule.get_current_week are that one rule, so from September 1 to that Wednesday they give the previous season (week 22), not the new one. (#791)
  • polars 2 required. The runtime pin is now polars>=2.0,<3 (conda recipe mirrored); polars 1.x is no longer supported, so code may use 2.x-only API such as the bin_* replacements for cut/qcut. The lock already resolved polars 2.0 on every supported Python, so nothing tested 1.x.
  • PWHL: pwhl_player_box(game_id) returns {"skaters": DataFrame, "goalies": DataFrame}, as fastRhockey's pwhl_player_box does and as the fastRhockey-pwhl-raw producer reads it. It used to return a single (always empty) DataFrame.
  • stats.ncaa.org fetch layer: a real 404 raises NoDataError after one request; a banned or exhausted proxy pool, an uncleared bm-verify challenge or the Terms gate raises AssetFetchError naming which. Both were RuntimeError; catch AssetFetchError instead (a missing proxy configuration is still RuntimeError). (#920)

Security​

  • Cache: the opt-in response cache stores bodies after credential scrubbing, not before, so a token or API key echoed in a body or URL never lands on disk. (#865)
  • Cached bodies: only the request's own credential values are scrubbed from a stored body (now including api_token= / user_key= params), so a signed media URL in the body (X-Amz-Signature=, Signature=) is served from the cache exactly as the live call returned it.
  • Redaction: error messages, retry log lines and cached URLs now also hide a URL's user:password@, appkey=, access_key=, subscription-key=, sig=, signature=, auth=, pass= and Authorization values, a Bearer / Basic credential and a whole Cookie: header line; a failed request's X-Api-Key / x-api-secret / X-Authorization headers are dropped with Authorization and Cookie.
  • Response cache: a request that authenticates outside its URL (an Authorization, Cookie, X-Api-Key or other credential header, or a session= holding cookies) is never cached, so a second credential in the same process or cache dir is no longer served the first one's body (legacy PFF Premium, api.nfl.com, NFL Pro, the Data API id map, KenPom / Her Hoop Stats sessions). cache_ttl=0 given as an int no longer raises AttributeError when a cache mode is on (every basketball runtime passes it). A body that cannot be cached, or a binary one (application/octet-stream, images, parquet, ...), is no longer JSON-decoded on every download.
  • Subscription logins: the KenPom / Her Hoop Stats session cache tells passwords apart (a changed password logs in again instead of reusing the old session for 30 minutes), and threads that miss it together log in once. The 247Sports guest token and the On3 buildId are minted once under a lock.
