Model lineage

Every bundled model artifact and every fitted constant in sdv-py should name the script that produced it, and that script should be one a reader can open. This page records where that holds and where it does not. tests/test_model_lineage.py keeps it honest: every dev/**.py or tools/**.py path cited from package source must be tracked by git or be listed under Known gaps below, a gap that becomes tracked must be removed from the list, and every bundled .ubj booster must have a row in the booster registry.

A script in another repository is cited as repo + path + the commit it was read at. "Byte-identical" means the bundled file's sha256 equals the GitHub release asset's digest (checked 2026-10-22).

Known gaps​

Cited from package source but not tracked. Lost means the script is in no branch's history (git log --all) and not on the maintainer's disk: the numbers it produced are recorded in the source but cannot be re-derived. Untracked means the script exists only in the maintainer's gitignored dev/ directory; committing it (under tools/, or force-added like the other tracked dev/ scripts) closes the gap.

Not cited from package source, so outside the test, but still gaps:

  • dev/mbb_prediction/train_in_game_wp.py (untracked) trained mbb_in_game_wp.ubj and wbb_in_game_wp.ubj.
  • cfb_cp_model.card.json, cfb_cp_model_air_yards.card.json and fd_model.card.json carry training_seasons: null and n_training_rows: null.
  • No NFL, MBB, NBA or MLB booster ships a card.
  • nfl-data's registry lists the NFL QBR fitting script as TODO; the trainer named above (cfb_qbr/qbr_xgb.R) is the one the 2.7 feature-order fix traced the artifact to, not an NFL-trained replacement.

Adding a model​

Cite the fitting script by a path that is tracked: put a new fitter under tools/fit_<what>.py (the tools/fit_cfb_wp_overtime.py pattern) rather than in the gitignored dev/, add the artifact's row above, and label any value that is a seed rather than a fit as seeded where it is defined.
