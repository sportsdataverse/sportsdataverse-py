# PFF Premium Stats Port — Implementation Plan (Track 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Wrap the `premium.pff.com/api/v1` surface (46 paths → 34 stat reports across two view families + 7 singletons, uniform over nfl/ncaa/aaf/ufl) as a codegen-generated flat-API stem with cookie auth, tidy polars parsers, returns-schemas, returns-table descriptions, docs entries, and gated tests — matching the `nba_stats` flat-API contract.

**Architecture:** One **normal generated flat stem** (`sportsdataverse/nfl/pff_core.py`, prefix `nfl`) whose wrappers carry `league` (enum `nfl/ncaa/aaf/ufl`) as an ordinary `extra_param` — generated by the **existing** codegen unchanged (no `generate.py` shim-mode, no Wave-0 codegen dependency). A small **hand-written runtime helper** `make_pff_league_module(namespace, league_slug)` (in `sportsdataverse/nfl/pff_league.py`) installs `functools.partial`-style league-bound copies of the core wrappers into a shim namespace (preserving `__name__`/`__qualname__`/`__doc__`, returning `__all__`). The **4 public shim modules** are then one-line hand-written files (`nfl/pff.py`, `cfb/pff.py`, `football/aaf/pff.py`, `football/ufl/pff.py`), each `__all__ = make_pff_league_module(globals(), "<slug>")`. Runtime (`nfl/pff_runtime.py`) supplies a cookie-auth injectable `_get`; parsers (`nfl/pff_parsers.py`) turn the `{report_key: ...}` envelope into tidy frames.

**Tech Stack:** Python 3.9–3.14, polars 1.x, uv, pytest. Generator modeled on `tools/codegen/gen_nba_stats.py`; runtime modeled on `sportsdataverse/nfl/nfl_api_runtime.py` (auth=true `_get`) + `sportsdataverse/nba/nba_stats_runtime.py` (injectable transport); parser modeled on `sportsdataverse/nba/nba_stats_parsers.py`. **Shim precedent:** the historical ESPN `make_league_module`/`_bind` factory (now retired from `sportsdataverse/_common_espn.py`, which today is only host constants + a `_get` re-export) — so `make_pff_league_module` is a **self-contained** `functools.partial` binder, NOT a wrapper over a live ESPN factory. The thin-league-shim intent also matches `sportsdataverse/wnba/wnba_team_roster.py`.

## Global Constraints

- **polars `>=1.0,<2.0`, modern API only.** `group_by` / `with_row_index` / `pl.len()` / `map_elements(..., return_dtype=)` / `how="full", coalesce=True` / `str.strip_chars`. Bool masks explicit: `pl.col("c") == True`. **Rust/polars regex has no lookaround** — use inline toggle `(?i)prefix(?-i: NAMES)`.
- **Returns-table column descriptions live ONLY in `tools/codegen/manual_column_descriptions.yaml`** (schema-keyed), NEVER in `schemas/**.yaml` (clobbered on re-capture / regen).
- **Codegen output is never hand-edited** (`pff_core.py`, generated `docs/docs/nfl/reference/*`, `schemas/native/pff/*`). Edit `tools/codegen/` sources (generator, `endpoints/pff.yaml`, templates) then run `uv run python tools/codegen/generate.py` and `--check` before commit. The 4 shim `pff.py` files, `pff_league.py`, `pff_runtime.py`, `pff_parsers.py` and the `pff-shim.md` doc stubs are **hand-written** (not codegen output).
- **ID / join-key dtype discipline:** PFF `player_id` / `franchise_id` / `league_id` are **integers** (`Int64`) — keep them int. `jersey_number` is a **zero-padded string** — keep it `Utf8`. `player_id` is **snake_case on the wire** (not `playerId`). Fix dtype at the parser boundary; assert agreement before any join.
- **uv for everything**: `uv run pytest|ruff|mypy|python`. New typed modules append to the `[tool.mypy] files` ratchet in `pyproject.toml`. After any `uv run mypy`/`pytest`, check `git status` for a silent `uv.lock` re-lock and `git checkout uv.lock` if unintended.
- **Live tests gated `@skip_if_no_pff_live` (env `SDV_PY_PFF_LIVE=1`)** — NOT the generic `SDV_PY_LIVE_TESTS` (paywalled + residential; mirrors the `skip_if_no_nba_stats_live` decision). No workflow sets this gate.
- **Conventional Commits, NO AI co-author trailers.** One logical change per commit; branch + PR, never push `main` directly.
- **Parallel-execution contention:** `FLAT_APIS` / `_FLAT_API_DOC` (`generate.py`) and `manual_column_descriptions.yaml` are shared append points across the sibling tracks; the **canonical `generate.py` re-run happens in the integration wave**, so every `generate.py` run in this plan is *self-verification only* (regenerate → confirm → commit your stem's slice).

  from __future__ import annotations
  import functools, inspect
  from sportsdataverse.nfl import pff_core

  def make_pff_league_module(namespace: dict, league_slug: str) -> list[str]:
      names: list[str] = []
      for name in pff_core.__all__:
          fn = getattr(pff_core, name)
          if "league" in inspect.signature(fn).parameters:
              bound = functools.partial(fn, league=league_slug)

          names.append(name)

## Notes / assumptions carried into implementation

- **Wrapper short naming** = `{view}_{report_slug}` where `report_slug` is the response envelope key (grounded in `pff-returns.md`: `/defense/run` → `run_defense_summary`, so `pff_facet_run_defense_summary`). The generator derives the slug from the OpenAPI response schema's single top-level property, NOT from the URL path segment — the two differ for several reports.
- **Matrix reports** (`/defense/coverage_matchup`, `/receiving/coverage`) both resolve to slug `receiving_coverage_stats` and the `{defenders,receivers,versus}` shape; the parser returns a dict of 3 sub-frames. Their returns-schema is the flattened long-form the parser emits (`note: matrix`).
- **AAF data thinness** (design risk): 2019-only, some reports empty — the empty-payload → zero-row path (Task 5) is what keeps aaf tests green; no aaf live fixture is required.
- **No codegen `generate.py` shim-mode dependency.** Per-league binding is the hand-written `make_pff_league_module` (Task 9) + 4 one-line shim modules (Task 10), modeled on the (now-retired) ESPN `make_league_module`/`_bind` intent — `functools.partial` + `functools.update_wrapper`. The core is a plain flat stem the existing codegen already handles.
- **Wave-0 foundation provides ONLY:** `@skip_if_no_pff_live` in `tests/conftest.py` (env `SDV_PY_PFF_LIVE=1`) and the documented T0 auth-spike finding. If the gate is absent when Task 13 runs, STOP and confirm the foundation landed first.
- **T0 auth spike** is a documented input (Task 4 guard): recon hypothesis is `_premium_key` carries the entitlement server-side; the supported path is user-supplied cookies via env / arg, so the plan does not depend on `pff_login` shipping.
