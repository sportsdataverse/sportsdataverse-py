NFL — additional Python functions — Play-by-play processing: espn_nfl

espn_nfl_pbp_nflverse​

espn_nfl_pbp_nflverse(plays: 'pl.DataFrame', schedule: 'Optional[pl.DataFrame]' = None, *, split_pats: 'bool' = True, participants: 'Optional[pl.DataFrame]' = None, players: 'Optional[pl.DataFrame]' = None, enrich: 'bool' = False) -> 'pl.DataFrame'

ESPN NFL play-by-play in nflverse play_by_play names, conventions and dtypes.

Turns ~sportsdataverse.nfl.NFLPlayProcess output (plays_frame, one game or many, or the published espn_nfl_pbp release) into nflverse's play-by-play: the keys, teams, field position, clock, down and distance, scores, timeouts, play types, the 0/1 play flags, yardage, nflfastR's description columns (run_gap, shotgun, out_of_bounds, penalty_type, ...), drive and series detail, with schedule nflverse's game columns (nflfastR's add_game_data), with players the GSIS player ids and names, and with enrich nflfastR's model columns (~sportsdataverse.nfl.ep_wp.enrich_nfl_pbp: EP / EPA / WP / WPA, try values, the air / YAC splits). It is additive: the cfbfastR-shape ESPN frame is not changed. Nothing is fetched unless enrich needs the xYAC model, which is not bundled (it is downloaded and cached on first use; without ESPN air yards its step is skipped).

Conventions follow nflverse, not ESPN: game_id is nflverse's YYYY_WW_AWAY_HOME and play_id the GSIS play id ESPN embeds in its play id (2006 on), so the frame joins nflverse play_by_play on (game_id, play_id). Teams come from the team ids and the game id, never from ESPN's abbreviations, in the franchise's current abbreviation as nflverse writes them (LA for the 2007 Rams). A kickoff belongs to the receiving team; a timeout row has no possession, down or field position; an offensive touchdown counts as a first down; a declined penalty is no penalty. With split_pats the try ESPN folds into a touchdown row (2014 on) gets its own extra_point / two-point row (~sportsdataverse.nfl.split_pat_rows) and the touchdown row's scores leave the try's points out.

Agreement with nflverse on whole seasons (2007, 2014, 2019, 2024) is 99%+ for most columns. The known gaps are ESPN's: desc is ESPN's text, not the NFL feed's; ESPN stamps some plays (scoring plays, whole 2024 games) with the clock after the snap; before 2009 many plays carry a stub text ("Rush", "Pass Completion"), so the text-derived columns (pass / run direction, completion, yards) are thin there; the timeouts are the processor's own count; a split PAT row's play_id is the touchdown's plus one (ESPN gives the try no id), so it does not join nflverse's PAT row.

Players: ESPN participant roles go to nflverse's slots by rules measured on whole seasons (two sackers are half_sack_1/2, a no-play keeps only the penalized player, a split try takes its touchdown's PAT players), and ESPN athlete ids go to GSIS through the players table's espn_id, never by name. fixed_drive is ESPN's own drive number, fixed_drive_result / series nflfastR's cascades on it. ESPN's air yards are empty, so cp / cpoe / xYAC / the air-yards splits stay null; qb_hit and jersey numbers are not built.

Parameters

ParameterTypeDefaultDescription
playsDataFrameNFLPlayProcess(...).plays_frame or the espn_nfl_pbp release (one or many games).
scheduleOptional[DataFrame]NoneThe nflverse schedule (~sportsdataverse.nfl.load_nfl_schedule). Adds the game columns, and supplies nflverse_game_id (from its espn id) when plays has none (NFLPlayProcess stamps it from ESPN's header since this release).
split_patsboolTrueGive each folded PAT / two-point try its own row, as nflverse does (default True).

playersOptional[DataFrame]NoneThe nflverse players table (~sportsdataverse.nfl.load_nfl_players; gsis_id, espn_id and short_name). Adds the <slot>_player_id / _player_name columns and the tackler / fumble teams.
enrichboolFalseRun ~sportsdataverse.nfl.ep_wp.enrich_nfl_pbp (without the fourth-down surface, which nflverse's play-by-play does not carry) on the view (default False).

Returns

One row per ESPN play (plus one per split try) in nflverse's column names, flags as Int64 0/1, measures as Float64, ids and names as strings, plus espn_game_id / espn_play_id to join back to ESPN. The schedule columns are present only with schedule, the player columns only with players, the model columns only with enrich.

Raises

ExceptionDescription
ValueErrorIf plays lacks the processor's columns, or carries no nflverse_game_id and no schedule (with game_id and espn) is given or the schedule lacks one of its games, or an id column is a float (a play / game id, or an athlete id in plays, participants or players), or players lacks gsis_id / espn_id, or a split try's synthetic id is already a play's (~sportsdataverse.nfl.split_pat_rows).

Example

from sportsdataverse.nfl import NFLPlayProcess, espn_nfl_pbp_nflverse, load_nfl_schedule
proc = NFLPlayProcess(gameId=401671740)
proc.espn_nfl_pbp()
proc.run_processing_pipeline()
pbp = espn_nfl_pbp_nflverse(proc.plays_frame, load_nfl_schedule([2024]))

# With GSIS player ids from ESPN's participants, and the model columns

from sportsdataverse.nfl import espn_nfl_play_participants, load_nfl_players
pbp = espn_nfl_pbp_nflverse(
    proc.plays_frame,
    participants=espn_nfl_play_participants(401671740),
    players=load_nfl_players(),
    enrich=True,
)
