# Documentation update

```bash
bash create_docs.sh
```

By default this regenerates the API reference into the unversioned **"next"**
tree at `docs/docs/<sport>/index.md`. Snapshotted versions under
`docs/versioned_docs/version-X.Y.Z/` are not touched.

To refresh a frozen version's pages (rare — usually you only do this if a
post-release docstring fix needs to ship to the published version), pass
`--version`:

```bash
bash create_docs.sh --version 0.0.51
```

If you add a new module to `sportsdataverse/`, also add it to the manual
`docs` sidebar in [docs/sidebars.ts](./docs/sidebars.ts) (the `tutorialSidebar`
is autogenerated and does not need updating).

per-sport pages (`sportsdataverse.<sport>.md`) are the ones we care about
— `create_docs.sh` copies them into the Docusaurus tree.

# Docusaurus 3 Website

This website is built using [Docusaurus 3](https://docusaurus.io/), a modern
static site generator.

- **Versions:** `docs/versions.json` lists the released versions; the
  unversioned `docs/docs/` tree is the in-development "next" surface.
  The version dropdown in the top-right navbar exposes both.
- **Config:** [docs/docusaurus.config.ts](./docs/docusaurus.config.ts) (typed).
- **Sidebars:** [docs/sidebars.ts](./docs/sidebars.ts) (typed). Versioned
  snapshots get a frozen JSON copy under `docs/versioned_sidebars/`.
- **MDX:** Per-file format detection (`markdown.format: 'detect'`) means the
  Sphinx-emitted `.md` files are parsed as CommonMark; only hand-authored
  `.mdx` files get the full MDX feature set. `create_docs.sh` post-processes
  the Sphinx output to escape bare `{` / `}` and `<factory>`-style literals
  that MDX 3 would otherwise misread as JSX.

## Installation

```console
yarn --cwd docs install
```

## Local Development

```console
yarn --cwd docs start
```

This starts a local dev server with hot reload. Most changes are reflected
live without a restart.

## Build

```console
yarn --cwd docs build
```

Generates the static site into `docs/build/`, ready for any static host.

## Type-check the config

```console
yarn --cwd docs typecheck
```

Catches mistakes in `docusaurus.config.ts` / `sidebars.ts` / `src/pages/*.tsx`.

## Cutting a new version

When you ship a new release:

```console
yarn --cwd docs docusaurus docs:version <new-version>
```

This snapshots the current `docs/docs/` tree into
`docs/versioned_docs/version-<new-version>/`, freezes the sidebar into
`docs/versioned_sidebars/version-<new-version>-sidebars.json`, and prepends
the new version to `docs/versions.json`. After snapshotting, update
`docs/docusaurus.config.ts` so the new version is referenced in the
`presets[0][1].docs.versions` block (and bump `lastVersion` if you want
visitors to land on it by default).

## Deployment

```console
GIT_USER=<Your GitHub username> USE_SSH=true yarn --cwd docs deploy
```

If you're using GitHub Pages, this builds the site and pushes the result to
the `gh-pages` branch.
