0.2.0b1 Release: October 26, 2026​

Highlights

0.2.0b1 is the beta of 0.2.0, the first release since 0.1.4 (0.1.5 was never published; its changes are folded in here). Install it with pip install --pre sportsdataverse; the 0.2.0 migration guide covers the sixteen breaking changes.

  • Failed fetches raise. AssetFetchError (the fetch failed), NoDataError (nothing there) and ValueError (a bad request) replace empty frames across ESPN, stats.nba.com, the generated flat APIs and HockeyTech.
  • polars 2 and Int64 ids. polars >=2.0,<3 is required, and parser id columns are Int64 at the boundary.
  • A reorganised package. Side leagues and EuroLeague live under sportsdataverse.basketball, cross-sport providers under sportsdataverse.providers, and the analytics helpers under sportsdataverse.analytics; the old import paths warn and keep working until 0.4.0. The G League gains its own nbagl_stats_* wrappers.
  • New sources. The PFF Developer API, Formula 1, EuroLeague, 24 international basketball and 12 European hockey families, kloppy soccer event data with SPADL and Expected Threat, Polymarket and Kalshi.
  • A rebuilt docs site. Pages titled by league name, returns tables in polars types, grouped leagues on the home page, new sdvplot charts in the tutorials, and an MCP docs server (sportsdataverse[mcp]).

Upgrade notes —

  • Errors: catch AssetFetchError where a loop must keep going; except NoDataError keeps skipping absent resources; except SportsDataverseError catches both, timeouts included; a ValueError means the call itself needs fixing. EmptyResponseWarning now fires only for a 2xx with an empty object. Code that caught requests.HTTPError from nfl_api_* or read exc.response must catch the new types (read the status from the message). HockeyTech wrappers that default the season raise when the seasons lookup fails; pass season_id= to skip it:

    import sportsdataverse as sdv
    from sportsdataverse.errors import AssetFetchError, NoDataError

    try:
        df = sdv.ahl_schedule()
    except NoDataError:
        df = None  # the fetch worked and there is nothing there: skip it
    except AssetFetchError:
        raise  # the fetch failed: retry later, never record it as empty

  • HockeyTech seasons: a caller who passed the start year to get a season should pass the end year; preseasons answer to the next year (resolve_season_id("ohl", season=2027, game_type="preseason") is the "2026 Pre-season"); pass season_id= where divisions listed side by side for one year are not told apart (e.g. BCHL 2024).

  • nba_stats / wnba_stats: pass season explicitly for a lockout or pandemic calendar; for every season pass an empty one (season_year_nullable="" for drafthistory, season_nullable="" for leaguegamefinder / playergamestreakfinder).

  • NFL loaders: replace load_nfl_ngs_passing, load_nfl_ngs_rushing and load_nfl_ngs_receiving with load_nfl_nextgen_stats(seasons, stat_type=...), and load_nfl_pfr_pass, load_nfl_pfr_weekly_pass, load_nfl_pfr_rush, load_nfl_pfr_weekly_rush, load_nfl_pfr_rec, load_nfl_pfr_weekly_rec, load_nfl_pfr_def and load_nfl_pfr_weekly_def with load_nfl_pfr_advstats(seasons, stat_type=..., summary_level=...).

  • NFL fantasy ids: code that joined or compared these ids as integers should cast its own side to pl.Utf8; call sportsdataverse.nfl.clear_cache() after upgrading, since cached frames keep their old dtypes (above all with cache_mode="filesystem").

Security​

  • Cache: the opt-in response cache stores bodies after credential scrubbing, not before, so a token or API key echoed in a body or URL never lands on disk. (#865)
  • Cached bodies: only the request's own credential values are scrubbed from a stored body (now including api_token= / user_key=), so a signed media URL in the body (X-Amz-Signature=) is served as the live call gave it. (#897)
  • Redaction: a Bearer / Basic credential and a whole Cookie: header line are hidden, and a failed request's X-Api-Key / x-api-secret / X-Authorization headers are dropped with Authorization and Cookie. (#897)
  • Redaction: error messages, retry log lines and cached URLs also hide a URL's user:password@, appkey=, access_key=, subscription-key=, sig=, signature=, auth=, pass= and Authorization values. (#897)
  • Response cache: cache_ttl=0 given as an int no longer raises AttributeError when a cache mode is on, and a body that cannot be cached, or a binary one (application/octet-stream, images, parquet), is not JSON-decoded. (#897)
  • Response cache: a request that authenticates outside its URL (an Authorization, Cookie, X-Api-Key or other credential header, or a session= holding cookies) is never cached, so a second credential in the same process or cache dir is not served the first one's body (PFF Premium, api.nfl.com, NFL Pro, KenPom, Her Hoop Stats). (#897)
  • Security: re-lock certifi (2026.10.23, compromised emSign intermediates), soupsieve, cryptography, nbconvert, mistune, tornado, virtualenv and opentelemetry-api past their advisories. The Python 3.10 resolution keeps Pillow 12.3 and virtualenv 21.14.5, whose fixes need Python 3.11+. (#1021)
  • Subscription logins: the KenPom / Her Hoop Stats session cache tells passwords apart (a changed password logs in again), threads that miss it together log in once, and the 247Sports token and On3 buildId are minted under a lock. (#897)
  • HTTP: a credential in a query string (The Odds API apiKey, HockeyTech key, Fox apikey, ...) reads REDACTED in every dl_utils.download log line, error message and chained exception; The Odds API wrappers raise AssetFetchError on a non-2xx answer instead of returning it as odds.
